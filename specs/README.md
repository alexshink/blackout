# Specs

Снимок **как устроено сейчас**, не бэклог и не второй README продукта.

Пишем spec, когда слой трогали или собираемся трогать. Агент в следующей задаче читает spec **до** кода.

После задачи по уже существующей spec — обновить её, если поведение, файлы, слои, «не сделано» или «дальше» реально изменились. Только важное: новая роль окна, другой вход хоткея, другой путь конфига, пункт плана закрыт/сменился. Пороги в пикселях, константы альфы и прочие мелочи в spec не тащим — они в коде. Если слой не изменился, spec не трогаем. Не вести changelog «что поправили в этом чате».

## Каркас файла

1. Одна строка: что пользователь делает.
2. Правила и слои / состояния — только то, без чего сломается правка.
3. Куда смотреть: файлы, функции, константы.
4. **Не сделано** — дыры текущего поведения, чтобы не принять их за фичу.
5. **Дальше** — кратко пункты из рабочего плана, которые касаются этой механики. Без этапов, без «почему».
6. Ссылки на смежные specs, если есть.

Без changelog, без цитат кода, без «как мы к этому пришли». Объём — чтобы прочитать за минуту.

Язык тела — русский; идентификаторы, пути, сообщения — как в проекте.

## Не сюда

- Обзор продукта, как пользоваться, таблица ОС — корневой [README.md](../README.md).
- Правка spec без правки кода — только если описание уже врало.
- Отдельные plan-файлы и очереди этапов.
